# 「光球对决」架构决策记录

## ADR-001 时间步长：固定 1/60s 累加器，不做渲染插值

- **背景**：GDD 钉死 1/60s 固定步长；命中判定、录制回放、突进位移都对步长一致性敏感。目标显示器可能 60/120/144Hz 混杂。
- **备选**：(a) 可变 dt；(b) 固定步 + 渲染插值；(c) 固定步 + 直接渲染最新逻辑态。
- **决策**：(c)。rAF 中累加器 while 循环推进逻辑，渲染直接画最新逻辑态，累加器增量钳制 ≤250ms。
- **理由**：录制回放以整数帧为轴，可变步会让录制数据不可靠（直接排除 a）；本项目移动无惯性、位移由端点插值保证，60Hz 逻辑态直接渲染的高频显示器抖动（≤7ms 级）对一击必杀的对决体验无感；(b) 的双缓冲状态插值代码量约 +15%，收益不成比例。
- **后果**：144Hz 显示器上视觉刷新有效 60Hz，可接受；若后续打磨期反馈拖尾不平滑，可在渲染层局部加位置插值（拖尾是纯装饰，改造成本低）。掉帧钳制防止"死亡螺旋"（一次追赶模拟多步导致进一步卡顿）。

## ADR-002 代码组织：单 HTML 文件内嵌多 class

- **背景**：约束"浏览器直接打开 index.html 即玩"。ES Module 在 file:// 协议下被 CORS 拦截，多文件 module 方案必须起本地服务器。
- **备选**：(a) 多文件 ES Module + 要求本地服务器；(b) 多文件经典 `<script>`（非 module）；(c) 单文件内嵌。
- **决策**：(c)。一个 index.html，IIFE 包裹，按 §1–§9 分节注释组织。
- **理由**：核心卖点即"双击即玩"，任何分发摩擦都是负资产。项目规模 ≤2500 行，单文件完全可控；经典多 script 方案 (b) 虽然也可用 file://，但引入加载顺序与全局命名空间管理，收益仅是"文件小一点"。
- **后果**：代码跳转靠编辑器全文搜索（现代编辑器无碍）；若未来扩展到多关卡/联网，届时再做拆分（拆分点已由分节注释预留，机械操作）。

## ADR-003 录制数据结构：Float32Array 轨迹帧 + 整数帧号稀疏事件流（混合）

- **背景**：镜像 AI 需要在 60Hz 精度回放轨迹，同时保留攻击/闪避时机。教学关期间 Recorder 全程录制，平局/死亡重开沿用不重录。
- **备选**：(a) 纯轨迹帧（每帧含全部状态含动作标志）；(b) 纯事件流（动作间线性插值位置）；(c) 混合。
- **决策**：(c)。轨迹 = Float32Array（每帧 2 float：x,y），动作 = 稀疏事件 `[{t:tick, type, dirAngle}]`，t 为整数帧号。
- **理由**：移动无惯性，两点线性插值即精确还原，但纯事件流 (b) 要在回放端重做插值器且事件密集时退化为帧序列——不如直接存帧；纯帧 (a) 把动作塞进轨迹会让每帧浪费 3 个槽位且类型字段丑陋。混合方案：轨迹内存紧凑（10 秒 ≈ 1200 帧仅 ~9.6KB）、回放 O(1) 寻帧，事件流天然表达"时机"。整数帧号消除浮点比较风险（t mod T 与事件对齐必须精确）。
- **后果**：Recorder 需要维护增长式 Float32Array（倍增扩容，finalize 时 slice 定容）；若未来动作需要精确到帧内相位（<16.7ms），需扩展事件字段（预留 `phase` 可选位）。幽灵攻击方向不录制、实时 atan2 瞄准——因此本结构不可用于"完全确定性重放"，镜像 AI 的模糊性是有意设计（GDD mirror-ai 已确认）。

## ADR-004 粒子实现：预分配 300 对象池 + 事件队列延迟发射

- **背景**：fx GDD 要求加法混合粒子（拖尾/残影/爆裂/火花），逻辑 60Hz。JS GC 抖动会直接掉帧。
- **备选**：(a) 每次即时 new/丢弃；(b) 预分配对象池；(c) 结构数组（SoA）+ 池。
- **决策**：(b)。启动时 new 300 个 Particle，freeList 索引栈分配回收；逻辑期只向 `fx.queue` push 事件，帧末统一 flush 发射。
- **理由**：(a) 每秒数百次分配产生 GC 停顿，hitstop 后爆裂瞬间（死亡 60+ 粒）风险最大；(c) 的 SoA 对 300 粒子是过度优化，可读性损失不值。池上限 300 即 GDD 预算：池满时新事件按优先级丢弃（burst > spark > trail，实现为 emit 时池满则尝试回收最老 trail）。逻辑期不碰渲染对象，保证逻辑可独立测试。
- **后果**：粒子超预算时会有视觉降级（拖尾先消失）而非掉帧，符合"性能可预期"目标；池上限写死 CONFIG.FX.POOL，调整一处即可。
