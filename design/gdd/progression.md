# GDD · 计数器与晋级规则细则（v2.0 新建）

> ⚠️ **v3.0 DEPRECATED 标注（主理人裁定）**：本文中「联机挑战池 / 联机boss池 / 终极boss」相关全部条目（含 100/1000 池上限与晋级线、CAS 并发语义、everBeaten）随 v3.0 联机模式改版**整体作废**。仍然有效：挑战自我（20 胜晋级）、单机boss（20 次被挑战成功删除 + 已打败玩家数仅计数）两池的计数语义，以及 DRAW/放弃/断线不计数的通用口径。

## 1. 概述
定义全部计数器、阈值（20/100/1000）、进度条口径、以及并发冲突的服务端权威语义。数字全部来自用户原文，不得增删。

## 2. 条目状态模型
一条条目（entry）= {replay, counters}。按所在池分四类计数结构：

| 池 | counters | 阈值行为 |
|---|---|---|
| 挑战自我 | defeatedPlayers (0→20) | 达 20 → 晋级单机boss；被击败 → 替换（计数随新条目归零） |
| 单机boss | challengedSuccess (0→20), defeatedPlayers (∞) | challengedSuccess 达 20 → 删除；defeatedPlayers 仅计数 |
| 联机挑战 | defeatedPlayers (0→1000), everBeaten (bool) | defeatedPlayers 达 1000 且 everBeaten=false → 晋级联机boss；everBeaten=true → 已被替换（不可能再晋级） |
| 联机boss | challengedSuccess (0→20), defeatedPlayers (0→1000) | challengedSuccess 达 20 → 删除；defeatedPlayers 达 1000 → 晋级终极boss；**先到先处理** |
| 终极boss | challengedSuccess (0→1000), defeatedPlayers (∞) | challengedSuccess 达 1000 → 删除；defeatedPlayers 仅计数 |

## 3. 计数口径
- **defeatedPlayers（已打败玩家数）**：+1 当且仅当一次完整对局以该条目幽灵击败挑战者结束。跨玩家、跨多次尝试累计，不因时间清零。
- **challengedSuccess（被挑战成功数）**：+1 当且仅当挑战者击败该条目幽灵。
- **everBeaten**：一旦该条目被打通即置 true（联机挑战池中随替换语义天然成立，见 §4）。
- **DRAW 不计数**：同帧对撞同 tick 的平局，双方计数器均不动，replay 不记录（保守口径）。
- **放弃/断线不计数**：未产生完整对局结果的上报一律忽略。

## 4. 服务端权威语义（联机三池）
1. **单一写者**：所有 counter 增减、替换、晋级、删除仅由服务端执行；客户端上报事件 {entryId, result:'win'|'lose', replay?}，服务端验证 entryId 仍存在后原子处理。
2. **替换幂等**（打通条目 X）：服务端 CAS——以 entryId+版本号原子执行「X 被打通 → X 原地替换为打通者 replay」。并发两人打通同一 X：先到达服务端的替换生效；后到者的 report 落在新条目上（新条目被其"打通"→ 再次替换）。语义：每个上报都消费于当时代码所见的条目版本，无丢失、无重复计数。
3. **晋级竞态先到先得**：条目同时逼近两个阈值（如联机boss 19/20 被击败 且 999/1000 打败玩家），两场对局并发结算 → 按 report 到达顺序处理，先触发阈值的规则生效（删除 or 晋级），另一规则因条目已消失而丢弃。设计接受此不确定性（用户原文未规定优先级，见歧义 #3）。
4. **serve_random 与结算解耦**：抽取返回条目快照；结算凭 entryId 定位服务端当前条目。若条目已被删除/晋级 → 该 report 幂等丢弃（对局已打完，玩家无感知）。
5. **进度条数据源**：客户端 HUD 的 N 值来自 serve 时快照 + 本局结束后的刷新响应；不实时轮询。
6. **localStorage 双池**：结构与服务端同构但单机权威（无并发），同一套阈值逻辑可直接复用。

## 5. 阈值速查（全部原文数字）
| 数字 | 含义 | 出处 |
|---|---|---|
| 100 | 联机挑战池条目上限 | 「上限每关记录100个操作」 |
| 1000 | 联机挑战条目晋级线（未被打通前提下打败玩家数） | 「累计被玩家挑战了1000次还未被打通」 |
| 1000 | 联机boss池条目上限 | 「联机boss关卡上限记录1000个」 |
| 20 | 联机boss被击败删除线 | 「累计被玩家挑战成功20次后会永久删除」 |
| 1000 | 联机boss晋级终极线（打败玩家数） | 「每当该操作挑战成功玩家1000次」 |
| 1000 | 终极boss被击败删除线 | 「被挑战成功1000次后会永久删除」 |
| 20 | 挑战自我晋级单机boss线 | 「累计打败玩家二十次」 |
| 20 | 单机boss被击败删除线 | 进度条原文「被挑战成功数：0/20」 |

## 6. 边界情况
1. 联机挑战条目在 999 时被打通 → 替换，计数归零，永远到不了 1000（"1000 次未被打通"的严格口径：中途任何一次被打通都重置旅程）。
2. 联机boss同时显示双进度条，两阈值独立，无交互。
3. 单机boss「已打败玩家数」无上限，展示为纯数字无分母。
4. 条目删除时其全部计数随之消失（无历史留存，lean 不做统计页）。
5. 替换产生的新条目 replay 若与池内已有条目完全相同 → 照常记录（用户原文未去重，见歧义 #8）。

## 7. 验收标准
- [ ] 8 个阈值数字与用户原文一一对应。
- [ ] 并发 CAS 替换语义在双打同条目场景无计数丢失（服务端测试约定，移交 E-21）。
- [ ] DRAW/断线/放弃三种无效对局均不触碰任何计数器。
- [ ] 挑战自我 20 胜晋级后槽位被第 20 个受害者 replay 顶替（非清空）。
