# GDD · 镜像复刻 AI（v1.1 修订版）

## 1. 概述
第一关的幽灵光球不是普通 AI：它逐帧回放玩家在教学关的全部操作，冲撞与防御方向/时机全部来自录制，**纯复刻**（v1.1 起取消实时瞄准——冲撞方向本就是移动方向，复刻即威胁）。本质是"确定性录制 + 偏移回放"。

## 2. 目标
- 玩家能明确认出"它在用我的招"（轨迹与出招习惯高相似）。
- 主客互换设计下威胁天然成立：幽灵回放路径的终点（教学关木桩位置）正是玩家第一关的重生点。

## 3. 输入（录制侧，教学关运行期间）【v1.1 修订】
Recorder 以固定 60Hz 采样，两组数据：
1. **轨迹数组 traj**: Float32Array，每帧 push {x, y}。
2. **动作事件 events**【v1.1 类型】：
   - {t, type:'charge', dirAngle} —— dirAngle = 起手锁定的冲撞方向（录制时实际移动方向）
   - {t, type:'guard_begin'} —— 进入防御姿态那帧
   - {t, type:'guard_end'} —— 松开右键那帧（非防抖结束帧）
   - 'attack'/'dodge' 类型废弃。

录制终止条件：教学关木桩死亡的那一帧 → 记录 T = 该帧总时长，冻结数据。

## 4. 规则（回放侧，第一关）【v1.1 修订】
- **位置回放**：ghostPos(t) = traj[floor(t/16.67)] + offset。
  offset = ghostSpawnPoint − 玩家教学关出生点（固定向量，整局不变；按当前出生点推导 = (0,0)，幽灵原样重走你的路）。
- **冲撞事件**：时间到达 → 幽灵若处于 IDLE 则进入起手（三段参数与玩家完全一致），方向 = 录制 dirAngle（纯复刻，不再 atan2 瞄准玩家）。
- **防御事件**：guard_begin → 幽灵若 IDLE 则进 GUARD（光晕、可挡玩家冲撞）；guard_end → 幽灵若 GUARD 则退出（幂等：若相位已非 GUARD 则安全忽略）。
- **确定性**：轨迹+动作+方向全部来自录制，回放严格镜像玩家教学关操作（ADR-003 原"不可完全确定性重放"条目失效）。
- **循环**：t ≥ T 时 t ← t mod T，轨迹数组取模续播，events 重新触发。幽灵无限循环直到分出胜负。
- **事件丢弃规则**（v1.1，技术侧裁定已确认）：幽灵处于 BOUNCE/GUARD 等非 IDLE 相位时到达的 charge 事件**丢弃不补发**——一次丢事件只损失一次进攻机会，不破坏镜像结构；幽灵格挡成功破盾后相位由命中裁决强制退出，后续录制的 guard_end 幂等忽略。
- 幽灵受击判定与玩家完全共用命中裁决（含对撞 startTick 比较、格挡规则），一击即死。

## 5. 参数
| 参数 | 值 | 单位 |
|---|---|---|
| 采样率 | 60 | Hz |
| 采样点大小 | 2×Float32（x,y） | - |
| 录制上限 | 600（10 分钟，≈144KB） | s |
| 循环方式 | t mod T | - |
| offset | ghostSpawn − tutorialSpawn | 向量 |

## 6. 边界情况【v1.1 修订】
1. **玩家全程站桩教学关** → traj 近似常量，幽灵几乎不动，但冲撞事件仍按录制方向触发（方向来自移动方向解析链，站桩时=鼠标方向兜底）→ 依然有威胁，自洽。
2. **录制超上限（>10 分钟）** → 截断：只保留最后 300s 轨迹，T 取截断后时长，重排 events 时间戳。（v1.1 实现取舍：MVP 可先不实现截断，增长式缓冲已支持长录制；列入 Should。）
3. **玩家在动作中途杀死木桩** → 录制在死亡帧冻结，幽灵永不复刻"残缺动作"（events 只录已完成的冲撞与已开始的防御）。
4. **平局/DRAW 重开** → 幽灵沿用同一份录制数据（offset 不变），不重录。
5. **首帧保护**：t=0 起前 500ms 幽灵不触发 events 中 t<500ms 的动作，防止开局面杀。
6. **性能**：traj 用 Float32Array 预分配（600s×60Hz×2×4B ≈ 288KB 上限），回放为 O(1) 索引，无 GC 压力。
7. **幽灵格挡成功** → 由命中裁决统一处理（与玩家同一条路径），录制的 guard_end 幂等忽略，不得报错。

## 7. 特效与反馈
- 幽灵外观：与玩家同形但色相偏移（玩家暖白，幽灵冷青）+ 半透明 0.85，一眼区分。
- 幽灵防御时同样显示呼吸光晕（视觉规则与玩家一致 = 强化"它在复刻你"的暗示）。
- 幽灵冲撞起手同样有蓄力拉丝预告。
- 循环接缝：t 归零瞬间幽灵周身泛一圈涟漪 + UI 角落"第 N 圈"计数（Should 级）。

## 8. 验收标准【v1.1 修订】
- [ ] 教学关走已知路线（如正方形绕圈）并定时冲撞/防御，第一关幽灵的轨迹、冲撞时机与方向、防御时机与录制数据逐帧一致（仅整体平移）。
- [ ] 幽灵冲撞方向 = 录制方向（与玩家实时位置无关）。
- [ ] 幽灵防御可格挡玩家冲撞，命中裁决与玩家侧对称（QA 对称性测试）。
- [ ] t 跨过 T 后无缝续播，无跳变、无 NaN。
- [ ] 玩家死亡重开后幽灵行为与首次完全一致（全确定性）。
- [ ] 幽灵非 IDLE 相位到达的事件安全丢弃，无异常、无相位污染。
- [ ] 录制 10 分钟内存占用 < 1MB。

## 依赖
- 上游：controls / charge（attack.md）/ guard 的状态迁移需暴露统一的事件钩子供 Recorder 采集；startTick 与录制事件 t 必须同源（Game.tick 整数计数）。
- 下游：level-flow.md 的衔接状态机消费本模块的 finalize() 接口。

## 已知风险与缓解
- 纯复刻下幽灵"聪明程度"完全取决于玩家教学关操作质量：若玩家教学关乱玩，第一关幽灵也乱——这是特性不是 bug（喂垃圾习惯=设计自己的敌人），但需在实现后实测"幽灵全程站桩"场景的可玩性，必要时在 Could 层加"幽灵低血性逼近"机制。

# v2.3 增量 · 水平镜像复刻（取代 v1.1「纯复刻录制方向」）

## A. 轨迹镜像
- 回放位置：**ghostPos(t) = M(traj[floor(t/16.67)]) + offset**，其中镜像算子 **M(x, y) = (1280 − x, y)**（绕屏幕中心水平镜像，y 不变）。
- 自洽验证：玩家出生 x=230 → M → 1050 = 幽灵出生点，**offset 自然归零**。
- **offset 公式保留**：offset = ghostSpawn − M(playerSpawn)，仍由 CONFIG 推导，勿硬编码 0（站位改动时公式自动适应）。

## B. 方向镜像（冲撞方向）
- charge 事件的 dirAngle 回放值：**dirAngle' = π − dirAngle**（cos 分量取反，即水平翻转）。
- 效果：玩家朝右撞 → 幽灵朝左撞（朝玩家半场）；玩家朝上撞（π/2）→ 不变（垂直方向自对称）。
- **用户语义锚点**：幽灵锁定玩家方向移动与攻击——玩家在左边时幽灵不会往右打；镜像变换保证幽灵的一切水平操作天然指向玩家侧。
- 移动方向无需单独镜像：轨迹回放已携带位移（镜像后的轨迹本身就是镜像移动）。

## C. 不变项
- guard_begin / guard_end 事件无方向，原样回放；事件 t 轴、循环 t mod T、首帧保护 500ms、录制格式全部不变。
- 「纯复刻录制方向」条款（v1.1 §4）**作废**。

## D. 边界情况
1. 玩家录制中越过中线越深（x > 640）→ 镜像后幽灵越贴近玩家半场（x' = 1280 − x < 640）——镜像语义自洽，幽灵会"追进"你的半场，接受并构成威胁来源。
2. 垂直冲撞（dirAngle = ±π/2）镜像后不变，逐帧与实体碰撞/对撞弹开正常交互。
3. 镜像后的幽灵轨迹若与玩家当前轨迹重叠 → 实体碰撞软推挤分离（v2.2 规则兜底，无特殊处理）。

## E. 验收断言【替换 v1.1 §8 对应条】
- [ ] 幽灵轨迹 = 录制轨迹的水平镜像（x 轴反射断言，逐帧比对）。
- [ ] 幽灵冲撞角度 = π − 录制角度（含垂直不变性用例）。
- [ ] CONFIG 推导 offset = (0, 0)（固定站位 + 镜像联合验证）。
- [ ] 玩家录制"朝右撞"场景：幽灵实际朝左（朝玩家出生侧）撞出。
