# GDD · 主菜单与界面系统（v2.0 新建）

> 【主理人裁定】本文 §2 原写"全部 UI 纯 Canvas 绘制"，与 architecture-v2.0-patch.md ADR-005（DOM overlay）冲突，**以 ADR-005 为准：菜单/子菜单/结算用 DOM overlay，canvas 保持纯对局渲染**。本文其余规格不变，交互语义按 DOM 实现。

## 1. 概述
主菜单是所有模式的入口，含 5 个一级选项；「挑战boss」展开二级菜单（3 项）。按钮可用性由对应资产池状态决定（灰显规则）。

## 2. 目标
- 玩家 10 秒内理解五模式去向；boss 存在性一目了然（灰显）。
- UI 形态：DOM overlay（ADR-005），按钮/hover/置灰/进度条走 DOM，canvas 保持纯对局。

## 3. 输入
鼠标移动（hover 高亮）、左键点击（进入/确认）、ESC（返回上一级/从对局退回菜单）。

## 4. 规则（IA 树与元素清单）

### 4.1 主菜单（一级）
| 选项 | 可用条件 | 行为 |
|---|---|---|
| 单机挑战 | 永远可用 | 进入 v1 流程：教学关→镜像关（产出 replay 的源头） |
| 联机挑战 | 在线 且 服务端联机池非空 | 连接后随机抽取一条 replay 开打；池空→灰显+提示"暂无幽灵，先在单机挑战创造一个" |
| 挑战自我 | 永远可用（本地存档） | 进入本地幽灵阶梯；首进无存档→先走单机挑战流程（见 modes.md §4） |
| 挑战boss | 永远可点（进入二级菜单） | 展开二级菜单 |
| 退出游戏 | 永远可用 | 弹确认框「确定退出游戏？」→ 是：window.close()；浏览器拦截关闭（常见于非脚本打开的标签页）→ 显示告别画面「感谢游玩，可关闭此标签页」 |

### 4.2 挑战boss（二级菜单，含「返回」项）
| 选项 | 灰显条件 | 进度条（文案原文） |
|---|---|---|
| 单机boss | 本地单机boss池为空 → 灰 | 「被挑战成功数：0/20」「已打败玩家数：0」 |
| 联机boss | 离线 或 服务端联机boss池为空 → 灰 | 「被挑战成功数：0/20」「已打败玩家数：0/1000」 |
| 终极boss | 离线 或 终极boss顺位队列为空 → 灰 | 「被挑战成功数：0/1000」「已打败玩家数：0」 |

### 4.3 灰显规则（统一口径）
- 灰显样式：文字与图标透明度 40%、去色、不可点击、无 hover 高亮。
- hover 灰显按钮显示原因 tooltip：「暂无 boss 存在」（池空）或「无法连接服务器」（离线）。
- 灰显状态在每次返回菜单时刷新（进入二级菜单时拉取一次池计数，不轮询）。

### 4.4 对局内 HUD（按模式）
| 模式 | HUD 进度条（文案原文） | 位置 |
|---|---|---|
| 单机boss | 「被挑战成功数：N/20」「已打败玩家数：N」 | 左上角纵排 |
| 联机挑战 | 「已打败玩家数：N/1000」（当前对手条目） | 左上角 |
| 联机boss | 「被挑战成功数：N/20」「已打败玩家数：N/1000」 | 左上角纵排 |
| 终极boss | 「被挑战成功数：N/1000」「已打败玩家数：N」 | 左上角纵排 |
| 挑战自我 | 「已打败玩家数：N/20」（新增口径，见歧义清单 #5） | 左上角 |

进度条样式：光条填充 + 数字文案，N 为实时值；终极boss 额外显示「终极boss 顺位：第 M 位」（M=当前队列头序号，仅计数展示）。

### 4.5 通用返回
- 对局内 ESC → 确认框「放弃本次挑战？」→ 是：返回主菜单（本次对局作废，不产生 replay、不计任何数）；否：继续。
- 二级菜单/模式内均有「返回」路径，逐级回退到主菜单。

## 5. 边界情况
1. 进入联机模式时断线 → 对局作废回主菜单 + toast「连接已断开」（不计数）。
2. 抽取的 replay 在对局中恰好被他人晋级/删除（联机资产被服务端移除）→ 本局照常打完（本地持有的副本仍有效），结算照常上报，服务端对已删除条目的上报做幂等丢弃。
3. window.close() 被拦截 → 告别画面兜底（不报错）。
4. localStorage 不可用（隐私模式）→ 挑战自我/单机boss 数据降级为内存态，顶部 toast「进度不会保存」。
5. 二级菜单三项全灰 → 仍可进入查看（三项灰显 + 返回）。

## 6. 特效与反馈
- 主菜单背景：缓慢漂浮的粒子光球（复用 fx 粒子池，低密度 ≤40 枚）。
- hover：选项光晕呼吸（复用 guard 光晕参数语言）。
- 灰显→可用瞬间（如 boss 池刚填充）：不主动动画（避免轮询驱动），下次进入时自然刷新。

## 7. 验收标准
- [ ] 五个一级选项 + 二级三选项全部可达且灰显条件正确（构造空池/非空池/离线三种环境验证）。
- [ ] 退出游戏在允许/拦截两种浏览器环境下均优雅处理。
- [ ] ESC 逐级返回且中途放弃不产生任何计数污染。
- [ ] HUD 进度条文案与用户原文逐字一致。

# v3.0 增量 · 菜单改版（联机对战 + 单机boss 拉平 + AI 演示入口）

> 依赖规格：ai-interface.md（OrbAI 接口语义）、mobile.md（触控）、architecture-v3.0-patch.md（网络与分期）。

## A. 主菜单 IA（v3.0 替换 v2.0 五项）
| 选项 | 可用条件 | 行为 |
|---|---|---|
| 单机挑战 | 永远可用 | v2.1 无限关卡链流程（不变） |
| 联机对战 | 永远可点（进 LAN 大厅屏） | 创建/加入房间（见 C 节）；离线时进入仍可看界面，连接失败给 toast |
| 挑战自我 | 永远可用 | 不变 |
| 单机boss | 本地池空 → 灰 | **从二级菜单拉平为一级按钮**（联机类 boss 删除后挑战boss 二级菜单取消） |
| AI 演示 | 永远可用（新增） | 本地 AI-vs-AI 展示对局（观战视角，结算可重开）；人机对局入口在 AI 编辑屏 |
| 退出游戏 | 永远可用 | 不变 |

- 原联机挑战/联机boss/终极boss 三项删除；挑战boss 二级菜单屏删除。

## B. AI 编辑屏（新增）
- 入口：主菜单「AI 演示」/ 联机房间座位配置处的「编辑 AI」。
- 元素：AI 代码粘贴框（等宽字体 textarea）、name 字段、内置示例 AI 下拉（至少 1 个内置 AI：追踪+时机冲撞）、保存到本地 slot（localStorage，≤3 个 slot）、「用此 AI 战斗」按钮（选本地人机对局的 AI 座位）/「用于 P1/P2」。
- 执行安全提示文案（ADR-009）：「AI 代码将在你的浏览器本地执行，请勿粘贴不可信代码」。

## C. 联机对战界面（三态）
- **大厅态**：创建房间（本机需已运行 server.js，页面显示 `node server.js` 引导与默认端口）/ 加入房间（IP 输入框 + 连接）。
- **房间态**：座位卡 P1/P2（点击入座/让座；human/AI 切换仅房主、未开局时）、观战席位列表（≤8）、房间状态、开始按钮（仅房主，双方座位就绪才可点）。
- **对局态**：复用 GAME 屏；观战者无输入 UI；结算显示三局两胜比分与「再来一局/退出房间」。
- 连接失败/断线：toast + 自动重连（30s 内恢复座位，期间座位由内置 AI 托管——以 architecture-v3.0-patch.md §1.4 为准）。

## D. 验收
- [ ] 新六项主菜单（含 AI 演示）全部可达，旧三项不残留。
- [ ] AI 编辑屏：粘贴→保存 slot→选入座位→对局中 AI 正常行动全链路。
- [ ] 联机三态流转与错误提示（房间满/房已散/连接失败）逐一验证。

# v3.1 更正 · TITLE 观感与房间配对流

## A. TITLE 开机屏（更正 v2.1 表述）
- **回滚 v1.0 观感**：黑底 + 标题 + 「点击屏幕开始」，点击一次 → 主菜单。v1.1 观感裁定作废，以此行为准（v2.1 的 TITLE 节其余交互规则不变：仅响应一次点击、ESC 永不回 TITLE）。

## B. AI 演示屏与 AI 编辑屏删除
- menu.md v3.0 节中「AI 演示」主菜单项与 B 节 AI 编辑屏**全部删除**。
- 设计口径：**OrbAI 保留为纯控制台 API**——任何 AI 打开游戏链接、在控制台接入 OrbAI 即可玩（含联机配对，见 ai-interface.md v3.1）。菜单不设 AI 专属界面。

## C. 联机房间配对码流（**作废** v3.0 C 节 IP 输入，替换如下）
- **创建房间**：点击 → 生成**房间码**，大字号展示 + 「复制」按钮。
- **加入房间**：粘贴房间码 → 客户端生成**应答码** → 玩家把应答码回传给房主（任意渠道粘贴给对方）→ 房主粘贴应答码确认 → 配对完成进房间态。
- 座位 UI **不再有 human/AI 下拉**：AI 经 OrbAI 占座（claimSeat，见 ai-interface.md v3.1），UI 仅显示座位归属（玩家#N / AI / 空）。
- **观战席位列表保留**（≤8，未占对战席的连接自动观战）。
- 房主「开始对局 / 重开」操作不变。

## 验收补充
- [ ] TITLE 为 v1.0 黑底观感，点击一次进主菜单。
- [ ] 菜单无任何 AI 演示/编辑入口；控制台 OrbAI 全功能可用。
- [ ] 房间码→应答码→确认 配对全流程在纯静态 Pages 页面可完成（无 IP 输入框）。
